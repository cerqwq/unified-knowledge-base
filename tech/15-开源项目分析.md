## 一、Vue.js 核心设计

### 1.1 响应式系统设计
```
设计目标：
1. 精确追踪 - 只更新需要更新的部分
2. 最小开销 - 避免不必要的计算
3. 易于使用 - 开发者无感知

实现方案：
- Vue 2: Object.defineProperty
- Vue 3: Proxy

选择 Proxy 的原因：
1. 可以监听新增属性
2. 可以监听删除属性
3. 可以监听数组索引
4. 性能更好
```

### 1.2 编译优化
```
静态提升：
- 将静态节点提升到渲染函数外
- 避免重复创建

Patch Flags：
- 标记动态内容类型
- 跳过静态内容比较

Block Tree：
- 只追踪动态节点
- 减少 Diff 范围

事件缓存：
- 缓存内联事件处理函数
- 避免不必要的更新
```

## 二、React 核心设计

### 2.1 Fiber 架构
```
设计目标：
1. 可中断 - 长任务可以暂停
2. 优先级 - 高优先级任务优先处理
3. 协调 - 高效的 Diff 算法

实现方式：
- 链表结构 - 方便中断和恢复
- 双缓冲 - current tree 和 workInProgress tree
- 时间切片 - requestIdleCallback

工作循环：
while (workInProgress !== null && !shouldYield()) {
    performUnitOfWork(workInProgress);
}
```

### 2.2 Hooks 设计
```
设计原则：
1. 纯函数 - 相同输入，相同输出
2. 无副作用 - 副作用放在 useEffect
3. 组合性 - 可以自由组合

实现要点：
- 调用顺序必须一致
- 存储在 fiber.memoizedState 链表
- 每次渲染创建新的闭包

常见 Hooks：
- useState - 状态管理
- useEffect - 副作用
- useMemo - 计算缓存
- useCallback - 函数缓存
- useRef - 引用
```

## 四、Next.js 核心设计

### 4.1 渲染模式
```
SSR (服务端渲染)：
- 每次请求在服务端生成 HTML
- 首屏快，SEO 好
- 服务器压力大

SSG (静态生成)：
- 构建时生成 HTML
- 极快，可 CDN 缓存
- 不适合动态内容

ISR (增量静态生成)：
- 静态生成 + 按需重新生成
- 兼顾性能和新鲜度

RSC (React Server Components)：
- 服务端组件不发送 JS 到客户端
- 直接访问数据库
- 自动代码分割
```

### 4.2 路由系统
```
文件系统路由：
- app/page.tsx → /
- app/about/page.tsx → /about
- app/blog/[slug]/page.tsx → /blog/:slug

布局系统：
- app/layout.tsx - 根布局
- app/dashboard/layout.tsx - 嵌套布局

加载状态：
- app/dashboard/loading.tsx - 加载 UI

错误处理：
- app/dashboard/error.tsx - 错误 UI
```

```typescript
// 装饰器实现
function Controller(prefix: string) {
    return function(target: Function) {
        Reflect.defineMetadata('path', prefix, target);
    };
}

function Get(path: string) {
    return function(target: any, key: string, descriptor: PropertyDescriptor) {
        Reflect.defineMetadata('method', 'GET', descriptor.value);
        Reflect.defineMetadata('path', path, descriptor.value);
    };
}

// 使用

class UserController {
    @Get(':id')
    getUser(@Param('id') id: string) {
        return { id };
    }
}

## 六、数据库设计

### 6.1 MySQL 索引设计
```
B+ 树特性：
- 非叶子节点只存索引
- 叶子节点存数据，双向链表
- 所有数据都在叶子节点

索引类型：
- 主键索引 - 聚簇索引
- 唯一索引 - 值唯一
- 普通索引 - 加速查询
- 联合索引 - 多列索引
- 全文索引 - 文本搜索

设计原则：
1. 选择性高的列建索引
2. 联合索引遵循最左前缀

## 七、微服务架构

### 7.1 服务拆分
```
拆分原则：
1. 单一职责 - 每个服务只做一件事
2. 高内聚低耦合 - 相关功能放一起
3. 业务边界 - 按业务领域拆分
4. 数据独立 - 每个服务独立数据库

常见模式：
- 按业务拆分 - 用户服务、订单服务
- 按功能拆分 - 认证服务、支付服务
- 按数据拆分 - 读服务、写服务
```

### 7.2 服务通信
```
同步通信：
- HTTP/REST - 简单，广泛支持
- gRPC - 高性能，强类型
- GraphQL - 灵活查询

异步通信：
- 消息队列 - 解耦，削峰
- 事件驱动 - 最终一致性
- 发布订阅 - 一对多

选择建议：
- 实时性要求高 → HTTP/gRPC
- 解耦要求高 → 消息队列
- 数据一致性要求高 → Saga 模式
```
