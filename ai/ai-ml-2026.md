# AI/ML 2026 知识库

## 大语言模型

### 开源模型
| 模型 | 参数量 | 特点 |
|------|--------|------|
| Llama 3.2 | 1B-90B | Meta 主力 |
| Qwen 3.5 | 0.6B-72B | 阿里通义 |
| Mistral | 7B-141B | 法国 Mistral |
| DeepSeek V3 | 671B | 中国深度求索 |
| Phi-4 | 14B | 微软小模型 |

### 模型选择策略
- 简单任务：1-3B 参数（快、省）
- 一般任务：7-14B 参数（平衡）
- 复杂任务：70B+ 参数（强、慢）
- 代码任务：专用代码模型

## 本地运行

### Ollama
- 最简单的本地 LLM 运行方式
- 支持多模型切换
- OpenAI 兼容 API

### llama.cpp
- C++ 实现，最高效
- 支持 GGUF 量化格式
- CPU/GPU 混合推理

### vLLM
- 高性能推理引擎
- PagedAttention 技术
- 适合生产环境

## RAG（检索增强生成）

### 流程
```
文档 → 分块 → 向量化 → 存储
查询 → 向量化 → 搜索 → 上下文注入 → LLM 生成
```

### 优化技巧
- 分块策略：按语义、按大小
- 向量模型：选择合适的 embedding
- 重排序：提高检索质量
- 上下文压缩：减少 token 使用

## Agent 框架

### LangChain
- 最成熟的框架
- 支持多种 LLM、工具、记忆
- LangGraph 用于复杂工作流

### CrewAI
- 多 Agent 协作
- 角色定义、任务分配
- 简单易用

### AutoGen
- 多 Agent 对话
- 人机协作
- 企业级

## 微调技术

### LoRA
- 低秩适配
- 只训练少量参数
- 适合消费级 GPU

### QLoRA
- 量化 LoRA
- 4bit 量化 + LoRA
- 最省内存

### 全量微调
- 需要大量 GPU
- 效果最好
- 成本最高

## 最佳实践

### 模型选择
1. 先试本地小模型
2. 不够再用云端大模型
3. 复杂任务用 Agent 框架

### 成本控制
- 压缩 prompt
- 缓存常见回答
- 使用本地模型处理简单任务
- 批量处理减少 API 调用

### 安全考虑
- 输入验证
- 输出过滤
- 防止 prompt 注入
- 敏感信息脱敏
